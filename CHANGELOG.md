## [Unreleased]

### Fixed
- **Dictation works on the page a host served.** The microphone was in the composer, but a press failed with "No speech service is chosen" even when the host had a provider: the page read the host's providers only once Settings, Voice was opened, and the default service, the operating system's, is not there in a browser. The app now reads them when the page opens (and again when the host comes back), a press waits for that, and a person who never chose a service gets the host's local provider; a provider they wrote themselves or a named service is only ever their own choice. A host that has not given the page's key the `voice` grant says so in words.
- **A folder on a Windows share works wherever a folder does.** The host names it `\\server\share\...` in the folder browser, `fs/info`, repository detection and Open in (it had answered `\\?\UNC\...`), runs git in it (git asks for `safe.directory` on a share and refused every command), makes a chat's folder from a `[sessions] workspace` template that starts with `\\server\share`, and opens a terminal there; `cmd.exe` cannot start in a share, so `terminal/open` says so in `notice`. The session list and the recent workspaces keep a share as one entry however its path was written, a protected-path entry and a remembered permission rule can name a path on a share, and a hook's allow checks it against the list.

### Added
- **The desktop app's own requests follow the system too.** What the app asks of a Canoa host it was told about (its list at `canoa.json`, the status probe of a saved connection, the terminal check) is sent by the host it runs through the new `network/fetch` request, which uses the host's network: the system's proxy and its login (Negotiate and NTLM included), the operating system's certificate verifier and the client certificate of its keystores, with `[host.network]` over them. The app's own HTTP library does none of that. Only the person running the host asks for it; a key is refused. A served page's requests stay its browser's, and a request that cannot reach the host fails and says so instead of going out another way.
- **A conversation in a window of its own, and a child's conversation, are read aloud too.** A pop-out window has Play beside Copy on each reply and voice mode's switch in its header; it plays no sound itself and asks the main window to, so the voice, the provider and the player are the same wherever the reply is shown (voice mode turned on in a window follows that window's conversation, and goes back to the one the main window shows when the window closes). A child's conversation, opened from the delegation row, has Play on its replies, and voice mode reads them as they arrive while it is shown.
- **Foundry Local and your OpenAI API key accounts are speech-to-text providers.** Settings, Voice offers a Whisper model of the Foundry Local service on the host (each recording is written to a temporary file on the host, handed to the service by its path and removed afterwards; the service's address is read whenever you dictate, and Canoa never loads the model, which the Foundry models page does, where a Whisper model's page also has Use as speech provider), and one offer for each OpenAI API key account you have in Canoa, named for the account so you know which key pays: the key is read from the account's store when you dictate and is never written to canoa.cfg or shown. A ChatGPT sign-in is not an API key and is listed as not offered, with the reason. `speech/enable` takes `foundry` and `openai_account:NAME`, a `speech_endpoint` table can say `request = "local_file"`, and `[speech.NAME]` tables may carry `account`, `service` and `service_address`.
- **The Office add-in on this computer can start Canoa, survives its restarts and can ask for a secret.** `canoa office-launcher`, a small program left running, holds the add-in's address while no Canoa runs: a pane opened then shows a page with **Start Canoa** (and an open pane shows the button when Canoa stops), which starts the host the home recorded with `native install`; the launcher lets go of the address as soon as a host holds the home. The keys the host admitted are kept in its home and held again after a restart, with their control grants, so the chat reconnects with no reload. `[host.web] office_secret = true` (off by default) makes the host keep a secret in `<home>/office/secret` and refuse the page's admission and start requests that do not carry it; `render.mjs --secret-file` puts it in the manifest, which keeps another account on a shared computer from being admitted.
- **Outlook, Word and Excel offer their tools to every session of the Canoa on the same computer.** While the Office pane is open, each session the host starts (the app's, the served page's, another pane's) is given `canoa-outlook`, `canoa-word` or `canoa-excel`: the open message (headers, body as text, attachments, conversation id), the document (text, selection, comments) or the workbook (selection, tables, ranges), through Office.js. A change (a reply form opened with text, an insert, a replacement, a comment, a range written) is asked first in a bar in the pane, once a call, and is refused when nobody answers in two minutes or the open item changed meanwhile; each answer says which item it came from. The pane registers on the host's `@tools` through its own page's requests (`/office/tools/`), and closing it takes its tools from every session. The Word and Excel manifest now asks for `ReadWriteDocument`. Run against stand-ins for Office.js, not in an Office client.

### Fixed
- **Foundry Local 0.14 lists its models in the Store again.** Its `model list -o json` answers `{"variants": [...]}`, which the host did not read, so a working install showed no models; the message for a stopped service names 0.14's `foundry server start`.
- **The extension's `connect()` fails when the agent ends the link right after its proof.** A Noise agent that turns a key away closes after the proof has finished; when that close came before the answer to `connect()`, the page had no connection number to hear it under and waited for ever on a link that was already over. It now rejects with `NetworkError`.
- **The extension's page API follows the settled contract.** `connect()` honours its `signal` (`AbortError`, and what was being opened is closed); `readable.cancel()`, `writable.close()` and `writable.abort()` end the connection as `page`, a message the agent sends after that is dropped, and a write after the end rejects with `InvalidStateError`. A grant that lasts until the tab closes is seen only by its own tab. A page's `session/cancel` closes the window asking about that session's permission request and answers the agent `cancelled`. Asking again for an agent already granted ends the connections on the old grant, and the old grant is never written back. A request window closes when its page goes, and nothing is granted to a page that has gone. A link the agent did not end in order closes as `failed`, not `agent`.
- **The secret tools' server refuses a connection another user owns on Linux.** Delegation's and the Store's servers already did; the secrets server answered any local user who held a bearer, such as one read from an agent's command line. The three now share one server.
- **The web app starts with no service worker, and draws every glyph.** A browser that had visited an earlier build kept its service worker, and Flutter's loader registered the build's own and waited up to 4 seconds for it ("prepareServiceWorker took more than 4000ms") before starting the app. The app now registers none, drops one an earlier build left, and its build no longer publishes `flutter_service_worker.js`. The fallback fonts the engine asks for when Roboto lacks a glyph (symbols, arrows, emoji, CJK, every script) were looked for beside the page and never put there, so each fetch failed; `build.py` now copies all 724 of them (20.7 MiB), pinned by SHA-256 in `tools/fallback_fonts.sha256`, from the deps branch's mirror, which `tools/mirror_deps.py` fills. The build reaches no network and stops when one is missing or changed.
