# canoa-launch

The portable `CanoaUI.exe` for Windows: one file that carries the built Canoa app folder, compressed, with its SHA-256, and
runs the app from a per-user folder. It is not published; the packaging step in `app/tool/build.py desktop --portable`
builds it, and [`docs/portable.md`](../../docs/portable.md) is the release recipe.

## What a start does

1. Reads the embedded archive's manifest after checking the archive against the SHA-256 fixed at build time.
2. Finds `%LOCALAPPDATA%\Canoa\<version>\`. Absent, or not exactly the manifest (a changed or missing file, one more file,
   a link inside, a different manifest copy): unpacks to a temporary sibling, checks every file against the manifest as it is
   written, and renames it into place. Otherwise reuses it, after hashing every file again.
3. Removes folders it made earlier, keeping the current version and the newest other one.
4. Starts `CanoaUI.exe` from the folder with its own arguments, waits, and exits with its status.

## What it refuses

- `%LOCALAPPDATA%\Canoa` or the version folder being a symbolic link or junction (any reparse point), not a folder, or not
  owned by someone else (accepted owners: the current user, the folder that holds it, Administrators and the system account,
  since a window started elevated makes Administrators-owned files). On Unix also a folder writable by others.
- A payload whose paths leave their folder, hold a drive, a stream (`:`), a device name or a name Windows would rewrite, repeat
  a name in another case, or name the launcher's own manifest copy.
- Running a file the manifest does not list, and an unpacked folder that holds a file it does not list.

It deletes only a directory that holds a manifest copy naming its own folder, or one of its own temporary names (`.unpack-*`,
`.old-*`, `.gone-*`).

## Building

`CANOA_LAUNCH_PAYLOAD=<payload.zip> cargo build --release -p canoa-launch --bin canoa-launch` embeds the archive
`canoa-pack <app folder> <version> <payload.zip>` made. Without the variable the launcher carries nothing and says so. The
archive is generated by the packaging step and never committed. The crate forbids `unsafe`; the owner of a folder is read
through `windows-permissions`, and the error box is `win-msgbox`.

## Limits

An unsigned launcher shows SmartScreen's "unknown publisher" warning. Between checking the folder and starting the app, a
process running as the same user could still change a file; the launcher defends against other users, a stale or damaged
copy, and a planted file, not against code already running as the user.
