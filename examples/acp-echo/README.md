# Canoa ACP v2 authenticated WSS reference

This **test fixture**, not an AI agent, echoes prompts after mutual Coqui peer proof. It never exposes browser control, MCP, filesystem or terminal tools. It binds to 127.0.0.1 by default.

1. Install Node 22+ and OpenSSL, then run npm install in this directory.
2. Open the Canoa connection dialog and copy the browser's own PeerId.
3. Create a server P-256 key: openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out identity.pem
4. Supply a TLS certificate trusted by the browser, such as a localhost certificate generated by mkcert. Do not disable certificate validation.
5. Set environment variables CANOA_CERT, CANOA_KEY, CANOA_IDENTITY_KEY, CANOA_ALLOWED_PEER_ID and run node server.mjs.
6. The server prints its PeerId. Verify it out of band and enter it into Canoa, using the wss:// endpoint. Leave the WebTransport field empty.

By default the fixture binds to loopback port 8765. The identity changes at every restart if CANOA_IDENTITY_KEY is omitted. Remote binding via CANOA_HOST is for controlled test networks only.

Pairing is **explicit**: CANOA_ALLOWED_PEER_ID must be the browser public PeerId, and the browser must pin the server public PeerId. The Coqui proof supplements TLS, not replaces it.

Run npm test for an end-to-end WSS/browser peer/ACP v2 echo session and an untrusted-peer rejection check.

Rust native authentication interoperability is separately tested in the coqui-peer repository; this fixture uses the canonical pinned JavaScript Coqui method.
