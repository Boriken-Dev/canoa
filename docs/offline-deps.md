## Offline dependencies

The [deps branch](https://github.com/Boriken-Dev/canoa/tree/deps) keeps everything a build reads from the network, as text: a cargo vendor folder for each Cargo lock, `pub/` with the Dart packages, and `cdn/` with the fonts and Office.js. The shared build tool, `tools/build.py` (a copy of the one in Boriken-Dev/agent-overlays, configured by `tools/build.cfg`, `python tools/build.py self check` keeps the copy equal), fills and checks it:

| Command | What it does |
| --- | --- |
| `python tools/build.py deps refresh` | `deps sync` (fetch, verify, remove) and the commit on the deps branch's checkout, which is on the branch `deps`; push that branch first, then main |
| `python tools/build.py deps check` | holds the checkout to every lock, the CDN index and the Office.js pin, and names what is missing, changed or stale; `--ref COMMIT` holds a commit of the repository to the scanner |
| `python tools/build.py scan --tree DEPS_DIR` | the scanner that refuses archives, executables, key files, pack files and opaque data: `PASS: 0 flagged` |
| `python tools/build.py offline env`, `offline run -- CMD` | the pub cache and cargo home a build runs under, and the command run under them |
| `python tools/build.py flutter precache-check`, `fonts-check`, `fonts-install` | what a Flutter checkout and a web build must hold |
| `python tools/build.py sdk check`, `sdk install` | every tool a build needs at an exact version (`tools/sdk.lock`), and its installation |

A refresh is also the [GitHub Actions workflow](https://github.com/Boriken-Dev/canoa/actions/workflows/deps.yml). `manifest.json` (format 2) records the commit it was made from and, for each vendor folder, its lock, the lock's SHA-256 and the crate count; for `pub/`, the packages and what was dropped; for `cdn/`, each file's hash; and for each tree, its commit and every file's hash. CanvasKit stays local by using `--no-web-resources-cdn`.

The fonts the web engine falls back to for a glyph Roboto lacks (symbols, arrows, emoji, CJK and every script: 727 files) are mirrored under `cdn/fonts.gstatic.com/s/`. `tools/cdn_files.json` pins each file by host, path and SHA-256, and `deps sync` downloads them and refuses a file that changed. After a Flutter upgrade `python tools/fallback_fonts.py pin [DEPS_DIR]` rewrites the font entries of that index from the SDK's engine, and its diff is the review. The web build runs `flutter fonts-check` (the fonts the engine asks for are exactly the index's) and `flutter fonts-install` (copy them from the deps checkout into `build/web/assets/fonts/fallback/`, verifying each digest), and stops, naming the file, when one is missing or differs; it never fetches them.

Office.js is mirrored whole, from its repository: `cdn/office-js/` holds the tree of one commit of github.com/OfficeDev/office-js, with its `LICENSE.md`, exactly as published (772 files at commit `498e88261bc5`). Nothing in it is renamed, filtered or rewritten, and it is not trimmed to what compiles: the owner asked for the library as published, and Microsoft's license terms let it be distributed only unmodified. It is the `[[deps.tree]]` `office-js` of `tools/build.cfg`, and `tools/office_js.json` pins the commit, each file's SHA-256 and the files the add-in's pane carries; `deps sync` fetches the commit's source archive over HTTPS (no clone) and refuses a tree that differs. `python tools/build.py deps tree-pin office-js COMMIT` moves the commit and the hashes, and `python tools/office_js.py pin [--commit SHA]` also derives the carried set from the loader of the commit it pins (the head of the `release` branch by default), the diff of the list being the review. `crates/canoa-host/build.rs` carries the files the add-in's pane loads, and `LICENSE.md`, from the deps checkout (`CANOA_DEPS`) into the host and checks each against the list; it never fetches, and without the mirror it stops, naming `CANOA_OFFICE_JS=cdn` as the way to have the add-in load Office.js from Microsoft's CDN instead. Nothing under `cdn/` is fetched by any build.

The mirror carries only what compilation needs: each hosted package without its `test`, `tests`, `example`, `examples`, `benchmark`, `benchmarks`, `doc`, `docs` and `.github` directories, and without any remaining file a malware or archive scanner would refuse. `manifest.json` records what was dropped. Git dependencies, such as `coqui-acp` and `coqui-transport-web`, are carried as source trees, not clones (a bare clone is pack files): `pub/git/<repository>-<revision>/` holds the repository at the revision `app/pubspec.lock` names, without `.git` and filtered like a hosted package. Pub reads a git package from its cache without touching git when the checkout folder `<repository>-<revision>` is there, so `offline env` seeds its pub cache with these folders (a `.git/pub-packages` list of the folders that hold a `pubspec.yaml`, which pub writes after cloning, and a bare repository of the remote that holds one empty commit and a replace ref from the locked revision to it, because pub asks that repository for the revision before it trusts the checkout and git's packs are not carried), and `flutter pub get --offline --enforce-lockfile` resolves hosted and git packages from the branch, with the lock unchanged. Never mirror tokens or private registry credentials.

### Building from the deps branch

Every kind of `python app/tool/build.py` (`pwa`, `chromium`, `office` and `desktop`) builds offline, and offline is the only default. It finds a checkout of the deps branch (`CANOA_DEPS`, else a detached worktree of `origin/deps` or `deps` that `python tools/build.py deps path` adds beside the repository as `<repository>-deps`) and asks `offline env` for the variables to run under: `PUB_CACHE` is `target/offline-pub-cache`, seeded from the branch (each git dependency from its `pub/git/`, else from the pub cache that already holds it at the locked revision; that cache is only read), and `CARGO_HOME` is a cargo home that vendors `Cargo.lock`. It then runs `flutter pub get --offline --enforce-lockfile` and builds with `--no-pub`.

Before it resolves anything the build runs `flutter precache-check` on the Flutter on `PATH`: it must be the commit, version, engine and Dart that `tools/sdk.lock` names, with the engine files for the target already in its cache. Every tool it starts has Flutter's storage address and telemetry off and cargo offline, so a file the SDK lacks fails instead of being downloaded. When anything is missing (the SDK is not the lock's or was not precached for the target, no deps checkout, a hosted package whose version or hash differs or is not mirrored, a git dependency neither on the branch nor in the pub cache, crates a vendor folder lacks, or `pub get --offline` failing), the build stops with what is missing and the commands that fill it: `python tools/build.py sdk install --groups app --prefix DIR` for the SDK (the mirror's checkout at the pin, precached from the release `engine-<hash>` of Boriken-Dev/flutter, never from Google's storage), `python tools/build.py deps refresh` for the branch. Nothing falls back to the network. `--online` is the one way to resolve from the network, for a developer refreshing the mirror; it does not look at the deps branch.

A `.env` at the repository root sets `FLUTTER_ROOT`, `PUB_CACHE`, `CANOA_DEPS`, `CARGO_HOME` and `RUSTUP_HOME`; a variable already in the environment wins. See `.env.example`.

### Crates

Each vendor folder is a cargo vendor directory: every package its lock names, from crates.io and from each pinned git revision, as `<name>-<version>/` with a `.cargo-checksum.json`. A package's tests, examples, benchmarks, fixtures, container files, developer scripts and tool dotfiles are left out, a git package has the workspace settings it inherits written into its manifest, and a binary that a build reads is written as text (an `include_bytes!` becomes an array literal, ring's prebuilt objects become hex that its `build.rs` decodes), so that no file in the branch is one a scanner would refuse.

A vendor directory holds one copy of a name and version, and two locks may need two sources of one package, so each lock has its own folder, all named as `[[deps.vendor]]` in `tools/build.cfg`:

| Folder | Lock | Used by |
| --- | --- | --- |
| `crates/` | `Cargo.lock` | the host, `canoa-ffi`, the app's native plugin |
| `crates-web_noise/` | `app/web_noise/Cargo.lock` | `app/tool/build_noise.py`: the Noise bridge pins `coqui-peer-noise` at a revision the workspace does not use |
| `crates-web_whisper/` | `app/web_whisper/Cargo.lock` | `app/tool/build_whisper.py` |
| `crates-wasm-bindgen-cli/` | the `Cargo.lock` packaged with `wasm-bindgen-cli`, the row `app wasm-bindgen-cli` of `tools/sdk.lock` (its SHA-256 is the `.crate` file's checksum in crates.io's index) | `python tools/build.py sdk install`, which runs `cargo install --offline --locked` on it |

`deps sync` makes each folder equal to its lock (fetching what is missing or changed and checking each crate's SHA-256 against the lock; the command line's own checksum against the lock row); `deps check` names what is missing, changed or stale; `deps use [--vendor FOLDER]` writes a cargo home outside the repository whose `config.toml` replaces crates.io and each git source by that folder and turns the network off (`crates/` unless `--vendor` says another). `--vendor` limits any of them to one folder. The branch's `.gitattributes` marks each folder `-text`, since each file's hash is in its `.cargo-checksum.json`. `tools/repo.py push` refreshes the branch when a vendor lock, `tools/sdk.lock`, the CDN index or the Office.js pin changed.

`python app/tool/build_noise.py` builds the Noise method from `crates-web_noise/` of the deps checkout (`--deps DEPS_DIR`, `CANOA_DEPS`, else the branch's worktree beside the repository) with the network off, as `python tools/build.py offline run --vendor crates-web_noise -- cargo build ...`, and `build_whisper.py` does the same from `crates-web_whisper/`. `wasm-bindgen`'s command line is `python tools/build.py sdk install --groups core,app --deps DEPS_DIR` (or `build_noise.py --install-bindgen`): built offline from `crates-wasm-bindgen-cli/`. Without a deps checkout they stop, and only `--online` builds from crates.io and GitHub. The `wasm32-unknown-unknown` target is rustup's and is not on the branch: `sdk install` installs it with the toolchain, and a build that finds it missing says `rustup target add wasm32-unknown-unknown` and does not add it.

`build.py` covers cargo the way it covers pub: when `crates/` covers `Cargo.lock` (package names, registry checksums and git commits; `deps check` does the whole comparison), the build runs with `CARGO_HOME` at that cargo home and `CARGO_NET_OFFLINE=true`; when it does not, the build stops with the first crate missing. The native plugin starts cargo itself, so `--locked` is not passed; with the network off cargo cannot change the lock. The cargo home replaces `~/.cargo/config.toml` for that build.
